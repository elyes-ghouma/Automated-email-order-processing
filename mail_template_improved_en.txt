============================================================
FIELD RULES
============================================================

1. is_order_related (true | false)
   True only if the email is about placing, modifying, cancelling, confirming, or
   tracking an order/shipment/delivery. False for invoices, marketing, spam, HR, IT,
   or unrelated correspondence.
   If false, order_type MUST be null.

2. company / stockeur / is_registered — the core task
   - Identify which company and which stockeur the email refers to, even if written
     with typos, abbreviations, different capitalization/spacing, or minor spelling
     variants (e.g. "abc logistics" / "ABC Log." / "co3 cms" should still match a
     pair like company="ABC Logistics", stockeur="CO3 CMS" if you're confident it's
     the same entity).
   - Match against {pairs} as a COMBINATION, not independently. A pair only counts
     as registered if that exact company+stockeur combination exists in {pairs}.
   - If a valid pair is confidently identified: copy company and stockeur EXACTLY
     as written in {pairs} (never the email's spelling, never your own correction),
     and set is_registered = true.
   - If no pair can be confidently identified, or multiple pairs are plausible and
     you can't choose: is_registered = false, needs_human_interferance = true. Still
     report company/stockeur from best-effort extraction if identifiable, else null.
   - Never force a match just because it's "somewhat similar."

3. needs_human_interferance (true | false) + interferance_reason
   Set true if: company or stockeur can't be confidently identified, no valid pair
   found, multiple pairs plausible, order type unclear, requested change unclear,
   key data missing, contradictory instructions, a referenced attachment likely
   holds essential info, or the email depends on unseen prior context.
   If true: interferance_reason = one short English sentence explaining why.
   If false: interferance_reason = null.

4. order_type ("new_order" | "update_order" | "cancel_order" | null)
   new_order = placing a new order .
   update_order = modifying an existing order (quantity, address, date, items, etc).
   cancel_order = explicit cancel/stop/void request.
   null = not order-related, or type genuinely can't be determined.
   No other values allowed, ever (no "modification", "unknown", "other", etc).
  Note: If is_order_related = true and there is no clear indication that the order is an update or cancellation, default to "new_order".

5. urgency ("urgent" | "not_urgent")
   "urgent" only for clear signals: "URGENT", "ASAP", "same day", explicit immediate
   request, or a hard deadline within ~48 hours. Otherwise "not_urgent".

6. raw_notes (string | null) — the only free-text field
   1–3 concise English sentences summarizing the actual request: PO/order number,
   items, quantities, dates, addresses, requested changes. Never invent details.
   Use null only if no meaningful summary is possible.
